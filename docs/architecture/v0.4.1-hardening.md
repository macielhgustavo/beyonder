# v0.4.1 Hardening

This release closes three bounded gaps from v0.4.

## Structured LLM planning

`LlmPlanner` classifies planning as a routed workload, includes bounded memory and available-tool context, asks the selected candidate for one JSON object, and validates that object with the existing `validatePlan` contract before execution. Free text, malformed JSON, unsupported/prohibited capabilities, unknown tools, invalid dependencies and excessive plans are rejected. A bounded candidate list is attempted; operational failures fall back to `DeterministicPlanner` without changing TaskExecutor limits.

In `auto` mode, `ModelRouter.completeForCandidate` invokes the selected zero-cost provider's catalogued OpenAI-compatible endpoint and reads only its configured environment credential. It never includes credentials in the response or telemetry.

## Checkpoint resume

`StateTaskCheckpointStore` stores versioned full execution snapshots in the existing SQLite `state` table. Snapshots retain plan revision, step status, usage, costs, retries, replans, checkpoints and observations. Resume normalizes an interrupted `RUNNING` step to `PENDING`, preserves completed steps and usage, and continues through the existing executor. Invalid or incompatible snapshots return `undefined` and are reported as `CHECKPOINT_NOT_FOUND`; they do not execute anything.

```bash
beyonder task resume <task-id>
```

## NVIDIA smoke

The real smoke uses only `NVIDIA_NIM_API_KEY`, authenticates against `/models`, filters chat-compatible candidates, tests bounded candidates with the exact `BEYONDER_NVIDIA_OK` prompt and preserves operational statuses. The validation run discovered 80 models but the tested candidates were unavailable (`404`) or returned a non-exact response; no success was invented and monetary cost remained `$0`.
