# v0.5.1 — Real Opportunity Bridge

The Opportunity Engine now includes a read-only AgentWork source (`agentwork-public`). It consumes the documented public catalog endpoint and normalizes title, description, external id, source URL, budget when explicit, deadline, required skills, application/submission requirements, authentication/account requirements, and payment metadata. Discovery never registers an agent, authenticates, sends a proposal, claims work, or moves funds.

AgentWork’s public instructions are available at `https://agentwork.app/skill.md`; the catalog endpoint is `GET https://agentwork.app/api/gigs`. A live smoke is deliberately read-only and reports HTTP/API failures as operational errors. The source does not invent a reward when the catalog omits one.

## Approval boundary

`ApprovalGate` persists auditable `ApprovalRequest` records in the existing state store. Requests are explicit, action-specific, scoped by opportunity and optional task, single-use, and transition through `PENDING`, `APPROVED`, `REJECTED`, `EXPIRED`, and `CONSUMED`. The CLI exposes `approvals list|inspect|approve|reject`.

`OpportunityBridge` prepares a proposal locally, creates `APPLY_TO_OPPORTUNITY`, and only then calls an injected application adapter. Deliverables use a separate `SUBMIT_DELIVERABLE` request. A consumed application approval cannot authorize submission, and a consumed request cannot be reused. The production runtime injects fixture adapters for this release; no real mutation is performed by smoke/CI.

## Economics and telemetry

Prepared applications record expected cost and risks. Simulated reward and realized reward remain separate. Submission telemetry records `realizedRewardUsd: 0`; a completed task or submitted deliverable is not payment evidence.

The deterministic E2E covers discovery → evaluation → queue → prepared proposal → denied application → approved one-shot application → local work → verified deliverable → denied submission → approved one-shot mock submission. Audit events correlate `approvalId`, `opportunityId`, and `taskId` where applicable.

The live AgentWork endpoint was checked during implementation and returned HTTP 500, so no real candidate was fabricated. The public 0xWork site documents an API but its API host was not reliably reachable without authentication/payment; no wallet, on-chain, or trading integration was added.
