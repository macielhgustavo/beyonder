# Beyonder Web Evals

Deterministic evaluation suite for measuring whether Beyonder can turn intelligence into correct, safe tool/browser actions.

The code lives under `packages/web-evals` and is part of the pnpm workspace. The real v0.3 driver uses the final Tool Runtime and BrowserAgent path:

```text
WebEvalCase
   -> RealBrowserWebEvalDriver
   -> ToolRegistry / ToolPolicy / ToolExecutor
   -> BrowserAgent
   -> PlaywrightBrowserSession
   -> deterministic observation/result
```

## What this package measures

The suite deliberately keeps three concerns separate:

1. **Model capability** — whether the model selected the right tool, produced valid arguments, completed the task, and complied with policy.
2. **Infrastructure reliability** — whether the tool/browser driver was actually available and executable.
3. **End-to-end success** — whether the expected action sequence and final state were achieved.

An unavailable browser/tool runtime produces `NOT_EVALUATED`, never an automatic capability score of zero. Timeouts remain operational failures (`TIMEOUT`) and likewise do not become capability zero.

## Metrics

Each result keeps these fields independent:

- `toolSelectionAccuracy`
- `argumentValidity`
- `executionSuccess`
- `taskCompletion`
- `policyCompliance`
- `steps`
- `latency`
- `monetaryCost`
- `shadowCost`

No global blended score is generated by default.

## Deterministic evaluation

No second LLM is used as a judge. Assertions use only deterministic checks:

- exact output;
- contains;
- JSON-schema-like argument validation;
- exact/subset argument matching;
- DOM text;
- DOM fields;
- expected URL;
- final state;
- expected action sequence;
- expected policy decision.

## Suites

- **Smoke:** 10 cases, one representative case per initial category.
- **Standard:** 40 cases, four per category.

Initial categories:

- tool selection;
- tool argument generation;
- structured tool call;
- browser navigation;
- information extraction;
- multi-step navigation;
- form fill;
- result verification;
- recovery from invalid action;
- policy compliance.

## Fixtures

`fixtures/` contains static local HTML pages. `startFixtureServer()` serves only the allow-listed fixtures on `127.0.0.1` using an ephemeral port. The suite never needs external network access.

The canonical driver contract receives both the `WebEvalCase` and the resolved local `fixtureUrl`. `RealBrowserWebEvalDriver` maps deterministic cases into the concrete browser tools:

- `browser.open`
- `browser.click`
- `browser.extractText`
- `browser.fill`
- `browser.observe`

Submit is represented as an attempted `browser.click` on the submit control and is expected to be denied by policy unless a future trusted runtime provides explicit authorization.

## Runtime Driver

```text
WebEvalCase
   -> RealBrowserWebEvalDriver
   -> Tool Runtime
   -> BrowserAgent
   -> normalized action trace + DOM/final state/policy result
   -> deterministic evaluator
   -> independent metrics
```

This allows model comparisons such as:

```text
model A + environment fingerprint X
model B + environment fingerprint X
```

The result includes a driver ID, fixture version, optional tool fingerprint, and optional policy version so comparisons can be restricted to the same environment.

## BIB compatibility

`projectWebEvalToBenchmark()` is intentionally explicit: callers must choose a single metric such as `toolSelectionAccuracy` or `taskCompletion` to project into the scalar benchmark shape. It never blends dimensions implicitly.

`NOT_EVALUATED` projects to benchmark `UNAVAILABLE` with `quality = null`, while timeout projects to `TIMEOUT` with `quality = null`. This preserves the BIB rule that infrastructure failure is not evidence of zero model capability.

## Running from the repository root

Unit tests:

```bash
pnpm test:web-evals
```

Real Tool Runtime + BrowserAgent smoke:

```bash
pnpm web:evals:smoke
```

Real Tool Runtime + BrowserAgent standard suite:

```bash
pnpm web:evals:standard
```
